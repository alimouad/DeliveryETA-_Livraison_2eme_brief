شرح مشروع توقع وقت التوصيل بالدارجة
====================================

الفكرة العامة
-------------
عندنا data ديال delivery، وبغينا الموديل يتوقع شحال غادي تاخذ التوصيلة بالدقائق.
العمود اللي بغينا نتوقعوه هو:

    Time_taken(min)

هاد العمود كنسميوه target أو y.

أما الأعمدة الأخرى، بحال المسافة، الطقس، traffic، نوع المركبة والساعة، كنستعملوهم باش نعاونو الموديل يتوقع الوقت. هادو كنسميوهم features أو X.


المرحلة 3: تجهيز البيانات وتدريب الموديلات
--------------------------------------------

1. فصل X و y

X فيها المعلومات اللي غادي نعطيو للموديل:
- distance_km: المسافة
- Weatherconditions: حالة الطقس
- Road_traffic_density: مستوى traffic
- Type_of_vehicle: نوع المركبة
- pickup_hour: ساعة pickup
- is_peak_hour: واش ساعة الذروة

y فيها الجواب الصحيح:
- Time_taken(min): الوقت الحقيقي ديال التوصيل

ID ما كنستعملوهش حيث غير رقم تعريفي ديال الطلب، وما عندوش معنى تنبؤي.


2. تقسيم البيانات 80/20

كنقسمو data لجوج أجزاء:
- 80% train: الموديل كيتعلم منهم
- 20% test: كنختبرو واش الموديل تعلم مزيان على data ما شافهاش

مثلا عندنا 41,953 صف:
- train فيه 33,562 صف
- test فيه 8,391 صف

مهم: test ما خاصوش يدخل فالتعلم، حيث بغينا نعرفو واش الموديل كيعمم مزيان.


3. معالجة القيم الناقصة NaN

كاينين 569 قيمة ناقصة فـ Weatherconditions.
ما كنحيدوش الصفوف كاملة، ولكن كنستعملو SimpleImputer:
- الأرقام الناقصة: كنعوضوها بالـ median
- النصوص الناقصة: كنعوضوها بأكثر قيمة متكررة

هاد العملية كتدار داخل Pipeline باش ما يكونش data leakage.


4. تحويل النصوص إلى أرقام Encoding

الموديل ما كيفهمش النصوص مباشرة.
مثلا Weatherconditions فيها Sunny و Rainy.
OneHotEncoder كيحولهم لأعمدة رقمية 0 و 1.

مثال:
Weather = Sunny
كيولي مثلا:
Weather_Sunny = 1
Weather_Rainy = 0

handle_unknown="ignore" كتعني إلا بان category جديدة فـ test، الموديل ما يطيحش.


5. توحيد scale ديال الأرقام Scaling

الأعمدة الرقمية ماشي كاملين عندهم نفس الحجم:
- pickup_hour بين 0 و 23
- distance_km ممكن تكون كبيرة
- coordinates عندها scale آخر

StandardScaler كيوحدهم باش الموديلات، خصوصا Linear Regression و Ridge، يخدمو مزيان.

الـ scaler كيتعلم غير من train، ومن بعد كيطبق نفس التحويل على test.


6. Pipeline

Pipeline كتجمع preprocessing والموديل فمسار واحد:

    missing values -> scaling/encoding -> model

الميزة ديالها أنها كتضمن نفس المعالجة فـ train و test، وكتحمي من data leakage.


7. الموديلات اللي جربنا

جربنا أربعة موديلات بنفس train و test:

- Linear Regression: موديل بسيط كيفترض علاقة خطية.
- Ridge: بحال Linear Regression ولكن فيه regularization باش ينقص التعقيد.
- Random Forest: مجموعة ديال decision trees، وكل شجرة كتساهم فالتوقع.
- Gradient Boosting: كيبني trees وحدة بوحدة، وكل tree كتصلح أخطاء اللي قبلها.


8. Metrics: كيفاش نقيسو الجودة

MAE:
متوسط الخطأ المطلق بالدقائق.
إلا كان MAE = 5.28، فهذا كيعني:

    الموديل كيغلط في المتوسط بحوالي 5.28 دقائق.

MSE:
متوسط مربع الأخطاء. كيعاقب الأخطاء الكبيرة بزاف، ولكن الوحدة ديالو ماشي دقائق مفهومة مباشرة.

RMSE:
الجذر ديال MSE، والوحدة ديالو هي الدقيقة.
كلما كان صغير، الموديل أحسن.

R²:
كيبين شحال من التغير فـ وقت التوصيل قدر الموديل يفسر.
كلما قرب لـ 1، أحسن.
مثلا R² = 0.48 كتعني الموديل فسر تقريبا 48% من الاختلاف فـ وقت التوصيل.


المرحلة 4: اختيار وتحسين أفضل موديل
--------------------------------------

1. اختيار الموديل

Gradient Boosting كان أحسن واحد فالمقارنة الأولى، لذلك اخترناه باش نحسنوه.


2. تحسين hyperparameters

Hyperparameters هما الإعدادات اللي كنحددوها قبل التدريب، بحال:
- عدد الأشجار n_estimators
- سرعة التعلم learning_rate
- عمق الشجرة max_depth
- أقل عدد ديال samples فالتقسيم

RandomizedSearchCV كيجرب إعدادات مختلفة، وكل إعداد كيتقيم بـ cross-validation.
من بعد كيختار أحسن إعداد حسب RMSE.


3. مقارنة train و test لاكتشاف overfitting

إلا كان train ممتاز بزاف و test ضعيف، فهذا overfitting.
يعني الموديل حفظ data ديال train وما قدرش يعمم.

النتائج ديالنا:
- Train MAE = 5.2625 دقيقة
- Test MAE = 5.2770 دقيقة
- Train R² = 0.4968
- Test R² = 0.4830

الفرق صغير، لذلك ما كاينش overfitting مهم.
الموديل خدام بشكل متقارب على data اللي تعلم منها وعلى data جديدة.


4. R² ajusté

R² ajusté بحال R² ولكن كياخذ بعين الاعتبار عدد features.
إلا زدنا features كثيرة بلا فائدة، R² ajusté يقدر ينقص.
هادشي كيساعدنا نعرفو واش features الجديدة مفيدة فعلا.

Test R² ajusté عندنا هو تقريبا 0.4815.


5. حفظ الموديل

كنحفظو final pipeline باستعمال joblib:

- models/final_delivery_model.joblib
  فيه preprocessing والموديل النهائي كامل.

- models/delivery_preprocessor.joblib
  فيه imputer و encoder و scaler.

من بعد نقدروا نحمّلو الموديل ونستعملوه باش يتوقع طلب جديد بلا ما نعاودو التدريب.


الخلاصة
-------

الفرق بين train و test صغير، وهذا كيعني أن الموديل ما حفظش data فقط، بل قدر يعمم بشكل مقبول.
